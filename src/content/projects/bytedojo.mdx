ByteDojo is an active engineering exploration into what a terminal-first training platform for developers looks like when built without the usual web abstractions.

## What's being explored

The core question: can you build a meaningful feedback loop for developer efficiency entirely inside a terminal emulator, with no GUI scaffolding?

**xterm.js** handles the terminal surface. It's capable enough for a structured training MVP — input capture, output rendering, cursor control — without pulling in a full terminal emulator binary.

**Interactive scenarios** are defined as state machines: expected keystrokes, timing constraints, recovery paths for mistakes. Each scenario has a defined success condition that the analysis pipeline can evaluate.

**Keystroke analysis** captures timing between keystrokes, not just the keys themselves. The gap between `d` and `w` in a vim motion tells you something about internalization that the motion alone doesn't.

**Efficiency feedback** is still being designed. The goal is signal, not noise — one number per session that tells you whether you got faster or slower at the thing you practiced.
