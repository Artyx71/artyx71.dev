Pressing `Ctrl+h` in a terminal splits into two cases: you're inside Neovim, or you're not. The plugin handles both with a single `is_vim` check in tmux.

## The is_vim check

```bash
is_vim="ps -o state= -o comm= -t '#{pane_tty}' \
  | grep -iqE '^[^TXZ ]+ +(\\S+\\/)?g?(view|l?vim|fzf)(diff)?$'"
```

tmux queries the process running in the active pane by its TTY. If the process name matches `vim`, `nvim`, `view`, or `fzf` — and is not stopped (`T`), zombie (`Z`), or dead (`X`) — the check passes.

The binding then becomes a conditional:

```
bind-key -n C-h if-shell "$is_vim" "send-keys C-h" "select-pane -L"
```

If vim is running: forward the raw keypress to the process. Neovim's plugin intercepts it and calls `<C-w>h`. If not: tmux handles it as pane selection.

## Why escape-time 0 matters

tmux has a built-in escape sequence delay (`escape-time`) to disambiguate `Esc` from `Esc+key` sequences. At the default 500ms, `C-h` inside vim could be swallowed into that buffer. Setting `escape-time 0` eliminates the ambiguity — the keypress is dispatched immediately.

## The fzf edge case

fzf runs as a full-screen TUI inside the pane. Without it in the `is_vim` pattern, `C-h` would close the fzf window by triggering `select-pane -L` at the tmux level instead of sending the key to fzf. The pattern includes `fzf` explicitly for this reason.

## Neovim side

The nvim plugin registers `C-h/j/k/l` in normal mode to call `winnr()` and check if movement would leave the current window. If yes — the cursor is already at the split boundary — it emits a tmux passthrough to move the pane. If no — it runs a normal `<C-w>` movement.

The result: one mental model, two runtimes. The boundary between editor splits and terminal panes disappears.
