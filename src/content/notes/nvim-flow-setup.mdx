Flow state breaks when the tool gets in the way. Most Neovim configs accumulate plugins without asking why. These five are different — each solves a concrete friction point.

## Harpoon over Telescope for daily navigation

Telescope is great for discovery: files you don't know the path to, symbols across a large codebase. For the 3–5 files you're actually editing right now, it's too many keypresses.

Harpoon keeps a per-project pinned list. `<leader>a` marks the current file. `Ctrl+1/2/3/4` jumps directly. No fuzzy prompt, no wait for indexing, no UI. The mental model shifts: you curate your working set consciously instead of searching every time.

The tradeoff: you have to maintain the list. Files you forget to add don't appear. For large-scale navigation or unfamiliar codebases, Telescope stays the right tool.

## better-escape: jk exits insert mode

The most frequent transition in Vim is insert → normal. Reaching for `Esc` interrupts hand position every time. `jk` typed fast fires the escape instead — hands stay on the home row.

The 200ms timeout is the tuning parameter. Too long: normal `j` in insert gets swallowed. Too short: fast typists escape accidentally. 200ms works for most people; adjust if you type `jk` in words often (JavaScript people: watch out for `object` keys).

## Smear cursor + mini.animate: spatial feedback

A cursor that teleports gives no sense of distance. When `gg` jumps 400 lines, you lose track of where you are in the file. Smear cursor draws a blur trail between positions; mini.animate traces a curved arc on large `j/k` jumps.

This sounds cosmetic. It isn't. The animation encodes distance and direction as visual information, which reduces the cognitive work of reorienting after a jump. It's the same reason smooth scrolling in browsers isn't just decoration.

## Pomodoro in the statusline

External timers break focus by living in a different window. The pomodoro component lives in lualine — no Alt-Tab, no phone. 45 minutes work, 15 minutes break. The cycle is visible in the same place you check LSP status.

The 45/15 split vs. the classic 25/5: 25 minutes is too short to reach deep work for complex tasks. 45 gives time to actually get into a problem. The 15-minute break is long enough to step away from the screen.

## Undotree: the cases git doesn't cover

Git doesn't record every keystroke. If you write something, undo it, write something else, and commit — the first version is gone. Undotree keeps the full branching undo history including dead branches that `u`/`Ctrl-r` can't reach.

The use case is specific: you wrote a function, decided it was wrong, rewrote it, realized the original was better. Without undotree, that's a rewrite from memory. With it, `<leader>u` shows the branch and you navigate back.
